# Design docs

Point-in-time design rationale: for one design, the strategy chosen, the trade-offs weighed, and the alternatives rejected. Docs are valid as of their date and never silently rewritten — amend or supersede. The trust label tells a session whether to rely or re-check: `verified <date>` (checked against actual code behaviour on that date), `unverified` (rescued or aged, not yet checked), `historical` (superseded by reality, kept as design history). Single decisions live in `../adr/` instead.
